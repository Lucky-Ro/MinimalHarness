# 从零实现 Agent 与接入真实 Bash：对话交接

整理于 2026-11-26。本次对话有两次开发交付：从零实现多会话 Agent，以及将最初只能运行三条命令的工具改成由轻量模型审核的真实 Bash。第二次交付时全量离线测试为 **209 项通过**。仓库后来还有独立的 CLI Effort 改造，接手当前代码时需同时参阅文末说明。

## 用户目标与验收场景

用户要求阅读原题和 TDD 提示词，完成开发和测试。最直接的验收方式是打开两个窗口：窗口一查上海天气并记下“带伞”，窗口二记下“写周报”。分别追问“我刚才记了什么？”，每个窗口应只回答本会话的待办。退出后，用 `/list` 和 `/use <id>` 可以找回原来的会话。[原题](topic.md) · [TDD 提示词](PROMPT_TDD.md)

开发按五个阶段推进：领域对象、审核器与端口、工具与存储、主循环与上下文压缩、模型适配与 CLI。各阶段先写失败用例，再实现并跑回归。测试离线执行，失败原因和修复记录保存在项目中。[分层规格](specs/) · [测试日志](TEST_LOG.md)

## 第一轮交付的设计决定

| 关注点 | 实现及原因 |
| --- | --- |
| Agent 主循环 | 自行实现，未引入 Agent 框架。主模型根据已注册工具的名称、描述和参数 Schema 决定直接回答或发起调用。每条调用先审核，再执行，将结果按调用 ID 写回模型。拒绝、未知工具和执行异常都能回流；默认最多循环 8 次。 |
| 会话与待办 | 完整历史保存在每会话独立的 JSONL 中。待办工具只使用系统注入的 `ToolContext.session_id` 定位文件。原子写入与会话锁保护持久化；恢复中断的工具批次时，为缺失结果补记错误，避免重复执行有副作用的命令。 |
| 上下文压缩 | 估算占用达到窗口的 70% 时，用轻量模型合并旧摘要与较早消息，保留近期消息及完整的工具调用与结果。成功后才保存新摘要并推进指针，原始历史保留。压缩失败会记入 trace，当轮继续，下次用户发消息再试。 |
| 模型与审核 | 主对话使用 OpenAI 兼容的原生 Function Calling。审核和摘要使用 `FLASH_MODEL`。默认 `composite` 按“规则 → 小模型”审核，规则拒绝会短路；也支持 `rule` 和 `llm`。 |
| 模块边界 | `agent/domain/` 定义消息、工具和角色，`agent/app/` 定义端口与编排，`agent/adapters/` 负责协议和 I/O，`agent/main.py` 统一组装。AST 测试检查依赖方向。 |

初次交付包含会话待办、模拟天气、AST 算术计算和受限命令四个工具。后续仓库复审补入本地模拟 `search`，真实 Bash 改造时已有五个注册工具。开发中修复过两个可复现的问题：macOS 大小写不敏感卷上的会话文件别名，以及将方括号开头的普通摘要误判为 JSON。[架构说明](Agent_Architecture.md) · [组装入口](../agent/main.py)

## 第二轮：为什么更换 Bash

用户明确要求“将这里的 bash 工具写成真正的 bash 工具，因为有小模型的验证”。初版只允许 `pwd`、`ls` 和字面文本 `echo`，正常管道在送达审核模型前便被拒绝。

改造后，默认路径为：规则检查已知高危操作 → 将完整脚本提交给轻量模型 → 批准后原样传给 `/bin/bash` → 返回 `stdout`、`stderr` 和实际退出码。审核拒绝或审核模型超时时不会启动脚本。Bash 可使用引号、变量、数组、循环、管道和重定向。[规则检查](../agent/adapters/command_policy.py) · [Bash 执行器](../agent/adapters/tools/bash.py)

每次调用启动新进程，会话间通过独立工作目录隔离。同一会话创建的文件可在后续调用中读回，默认位置为 `data/bash/<会话ID>.work/`。子进程使用独立环境，关闭网络，执行限时 5 秒，标准输出和错误输出合计限额 1 MiB。macOS 使用系统沙箱，Linux 后端使用 bubblewrap。[进程监督](../agent/adapters/tools/_bash_process.py)

入口集成测试使用离线模型驱动真实执行器：同一条含 `tr`、`tee` 的管道在获批时输出 `DEEP SKY` 并写入 `approved.txt`；拒绝和超时分支均未创建该文件。macOS 已实际执行。Linux 当时验证了启动参数，仍缺少实机执行证据。Codex 外层沙箱曾阻止嵌套启用 macOS 沙箱，正常 macOS 环境复测通过。[入口测试](../tests/test_main.py) · [工具测试](../tests/test_tools_and_store.py)

```bash
.venv/bin/python -m agent.main
```

真实对话需要配置 `OPENAI_API_KEY`；离线测试无需凭证。接口地址、主模型、轻量模型、审核模式和数据目录的配置见 [README](../README.md) 和[环境变量示例](../.env.example)。
